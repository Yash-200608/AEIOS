# ADR-012: BME688 as Environmental / Gas-Feature Sensor

- **Status:** Accepted  
- **Date:** 2026-09-11  
- **Gate:** Post–Gate C reconciliation (C-03)

## Context

Gate A documents and FAS name Bosch **BME680**. Locked hardware and Context Files 01–02 specify **BME688** (T/RH/pressure + gas-response features). The parts are related; AEIOS must not treat gas resistance as generic ppm.

## Decision

1. **Target hardware is BME688** on the shared I²C bus (address 0x76 or 0x77 via SDO) with SCD41 at 0x62.
2. Use BME688 for temperature, humidity, pressure, and **gas-response features**.
3. Do not present BME gas output as a universally calibrated multi-gas ppm analyzer.
4. Preserve configuration/model version (including BSEC profile if used) with each observation.
5. Implementation maps onto the existing ESP-IDF driver interface (`aeios_driver_ops_t`); no PlatformIO tree.

## Alternatives considered

| Alternative | Why rejected |
|-------------|--------------|
| Keep BME680 as the named part | Contradicts locked procurement |
| One `calibration()` hiding 680 vs 688 | Different configs/features; hide-the-part is not a contract |

## Rationale

Matches the board that will be wired. Semantics stay “context + gas feature,” consistent with MQ135 not being ppm.

## Consequences

- Firmware registry/stub names use `bme688` (not `bme680`).
- DOC-004 and FAS driver tables require controlled revisions.
- Historical evidence packages that say `bme680` remain valid as D1-era records.
